# ISA-1 — revisão 6.6
Proposta: VGA 640x480, 59,94 Hz, RGB222, pixels lógicos 160x120. Clock de grupos 6,29375 MHz (25,175 MHz / 4). Contador horizontal 0..199, ativo 0..159, HSYNC baixo 164..187. Vertical 0..524, ativo 0..479, VSYNC baixo 490..491. Contadores síncronos, sinais registrados; alinhar blanking ao pipeline de dados. Referência: https://projectf.io/posts/video-timings-vga-720p-1080p/.
VRAM 32 KiB, endereço (linha lógica << 8) | coluna; 19200 bytes úteis, 30720 bytes de espaço com stride, 2048 bytes ao final. Repetir cada linha quatro vezes; não é necessário multiplicador de endereço. 2 bits por canal, dois bits livres por byte.
Acesso de vídeo a cada 158,88 ns em área ativa. Não assumir que cabe acesso CPU no mesmo intervalo. Primeiro estudar escrita no blanking, com handshake WAIT e sincronização entre domínios. 28200 slots de blanking por quadro são teto ideal, não throughput garantido. CPU continua executando fora de acessos VRAM. Prever prefetch no fim do blanking. Escritas protegidas e exclusão de drivers conforme rev 5.9. Não há simulação elétrica.
DAC ideal por canal: 1400 ohms LSB e 700 ohms MSB em carga 75 ohms, saídas 0/5 V push-pull. Níveis ideais 0, 0,2308, 0,4615, 0,6923 V (ver JSON para valores calculados). Verificar VOH/VOL, corrente, tolerância e carga real; não é circuito aprovado.
Contadores candidatos: 2 HC163 horizontal, 3 HC163 vertical; clock comum e enable vertical no fim da linha. 4 HC157 para selecionar endereço de VRAM (15 bits); latch RGB e decodificação/controle adicionais, ainda não BOM. Não usar carry como clock. Conversor ativo VGA->HDMI precisa aceitar 640x480; testar com Arzopa antes de compra definitiva. TFT SPI permanece alternativa. Modelo Python enumera quadro e endereçamento, não comprova temporização de CI, DAC ou conversor.
